# Documentation Style & Reading Guide

This documentation uses a consistent visual language for fast scanning.

## Reading conventions
- `MUST`: release-critical requirement.
- `SHOULD`: strongly recommended.
- `MAY`: optional or future enhancement.
- `P0`: critical foundation.
- `P1`: high priority.
- `P2`: later enhancement.

## Suggested Markdown viewer settings
For the cleanest reading experience, use a Markdown viewer that supports:
- GitHub-flavoured Markdown.
- Mermaid diagrams.
- Syntax highlighting.
- Table rendering.
- Light and dark themes.
- Sticky table of contents.
- Comfortable reading width.

## Recommended visual theme
- Background: soft neutral or deep navy.
- Surface: white / charcoal.
- Accent: indigo or electric blue.
- Success: green.
- Warning: amber.
- Danger: restrained red.
- Body line height: 1.6–1.75.
- Content width: approximately 900–1100 px.
- Headings: strong hierarchy with generous spacing.
- Code blocks: distinct surface and horizontal scrolling.

## Theme modes specified for the product
1. Light
2. Dark
3. System
4. Dim / low-glare
5. High contrast
6. Optional Warm Paper / Sepia
7. Optional custom accent colour

Markdown itself does not force a viewer's theme. The theme is controlled by the app or Markdown reader used to open these files.
